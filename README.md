# cascade-agent: каскадный VPN (Xray, VLESS + XHTTP + Reality) двумя командами

Скрипт запускается на отдельной «управляющей» машине. Вы даёте ему два сервера (адрес и пароль root) и число пользователей.
Он ставит и настраивает всё сам, проверяет каждый шаг, включает fail2ban и файрвол, выдаёт ссылки и (после вашего «работает») меняет пароли серверов.

    клиент --> СЕРВЕР 1 (вход) --> СЕРВЕР 2 (выход) --> интернет

## Требования

**Управляющая машина** (там живёт скрипт; НЕ должна быть одним из двух серверов)
- Ubuntu 22.04/24.04 или Debian 12, доступ root
- 1 vCPU, 512 МБ ОЗУ (рекомендуется 1 ГБ), 2 ГБ диска
- Публичный IPv4, лучше постоянный (он вносится в белый список fail2ban)
- Исходящий доступ: SSH к целевым серверам; HTTPS к github.com, raw.githubusercontent.com, ipinfo.io, api.ipify.org

**Каждый из двух серверов**
- Ubuntu 22.04/24.04, x86_64 (проверено: Ubuntu 24.04.5)
- Чистая установка: Xray не установлен, порт 443 свободен
- Вход root по паролю включён, публичный IPv4
- 1 ГБ ОЗУ (проверено на 961 МБ; скрипт добавляет swap 1 ГБ), свободно от 5 ГБ диска (лучше 10)
- Исходящий интернет (GitHub для установки Xray и геоданных)
- Сервер 1 должен достучаться до порта 443 сервера 2 по IPv4 (IPv6 не обязателен)

## Установка (на управляющей машине, от root)

    bash cascade-agent-installer.sh

Каталог по умолчанию /opt/cascade-agent (другой: INSTALL_DIR=/путь). Команда запуска: `cascade-vpn`.
Повторный запуск установщика обновляет скрипты и не трогает журналы.

## Работа

    cascade-vpn

Скрипт спросит: сервер 1 (`root@IP` или `ssh root@IP -p 2222`), пароль, сервер 2, пароль, число пользователей, часовой пояс (Москва = 3).
Он сам запустится внутри tmux. Если SSH оборвётся, вернуться: `tmux attach -t cascade`.
Весь цикл 10-15 минут. В конце: таблица этапов, ссылки (один раз), вопрос «работает?».
Сначала подключитесь по ссылке и откройте https://api.ipify.org: должен показаться IP сервера 2.
Только после этого напишите `работает`: скрипт сменит пароли и покажет новые (один раз, сохраните сразу).
Любой другой ответ оставит пароли прежними.

## Этапы

1. Проверка серверов (только чтение; если Xray уже есть, остановится)
2. Обновление системы, пакеты, swap, перезагрузка при необходимости (по одному серверу)
3. Установка Xray (версии установщиков зафиксированы хэшами)
4. Каскад: сайты маскировки по стране сервера, каскад по IPv6 или (если закрыт) IPv4
5. Пользователи user1..userN, самопроверка цепочки
6. Маршрутизация по стране сервера 1 (RU: российское напрямую; не RU: всё через каскад), автообновление геоданных по воскресеньям в 04:00
7. fail2ban и файрвол ufw с 5-минутной страховкой (сервер 2, затем сервер 1)
8. Проверка каждой ссылки настоящим клиентом, выдача ссылок
9. Смена паролей после подтверждения

## Прочие команды

    SCRIPT=final.sh cascade-vpn    # пара уже настроена: перепроверить и выдать ссылки заново, затем смена паролей
    SCRIPT=passwd.sh cascade-vpn   # только смена паролей
    SCRIPT=inspect.sh cascade-vpn  # осмотр серверов (только чтение)
    SCRIPT=reset.sh cascade-vpn    # СТЕРЕТЬ Xray/fail2ban/ufw (только тестовые серверы!)
    /opt/cascade-agent/checklink.sh   # проверить vless-ссылку настоящим клиентом
    FORCE_RU=1 cascade-vpn         # считать сервер 1 российским, если страна не определилась
    SKIP_EXT=1 cascade-vpn         # пропустить внешнюю проверку ссылок
    NO_TMUX=1 cascade-vpn          # не использовать tmux

## Безопасность

- Пароли держатся только в памяти процесса; в файлы и журналы не пишутся. Ссылки показываются один раз и в журналы не пишутся.
- Журналы: /opt/cascade-agent/jobs/<номер>/job.log (права 600).
- После смены пароля у скрипта доступа к серверам нет. Рекомендуется перейти на вход по SSH-ключу и отключить пароль (отдельная задача).
- Файрвол включается с таймером: если проверки не прошли, он сам выключится через 5 минут.
- Xray предупреждает, что очень известные сайты маскировки (apple.com и т.п.) повышают риск блокировки IP. Скрипт сначала берёт сайты страны сервера.

## Частые проблемы

| Симптом | Что делать |
|---|---|
| «уже есть Xray» | Это защита. Для тестовых серверов: SCRIPT=reset.sh |
| Внешняя проверка ссылок FAIL | Серверы настроены. Смотрите журнал; повтор: SCRIPT=final.sh |
| Ссылки проходят проверку, а у вас не подключается | Блокировка в вашей сети или у провайдера: проверьте команду из блока ссылок, попробуйте другую сеть; сайт маскировки можно сменить |
| После файрвола нет доступа | Подождите 310 секунд, файрвол выключится сам |
| Сервер не вернулся после перезагрузки | Нужна консоль хостинга |
| Ошибка «пароль не принят» | Проверьте пароль и что вход root по паролю разрешён |

## Не проверено

Проверялась одна пара серверов (Латвия, Рига, Ubuntu 24.04, IPv6 между серверами закрыт хостером). Не проверены: сервер 1 в РФ (российские правила), нестандартный SSH-порт, Debian, arm64, много пользователей, сервер без IPv6 совсем, запуск внутри tmux, пересчёт расписания по часовому поясу сервера. Перед боевым использованием прогоните на тестовой паре.
